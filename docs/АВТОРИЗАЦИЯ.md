# Доступ к API

После применения миграций создаём первого администратора командой `poetry run python -m schedule_service.create_admin`. Команда запрашивает имя и пароль в терминале и работает, только если таблица пользователей пуста. Пароль не передаётся через аргументы командной строки. Для работы с аккаунтами нужна защищённая база данных и HTTPS.

В работающем контейнере приложения создаём администратора командой `docker compose exec app python -m schedule_service.create_admin`. Для production-файла Compose добавляем параметр `-f docker-compose.prod.yml` перед `exec`.

`POST /api/v1/auth/login` принимает JSON с полями `username` и `password` и возвращает `access_token`, `token_type` и срок действия `expires_in` в секундах. В последующих запросах передаём заголовок `Authorization: Bearer <access_token>`. Срок сессии задаётся настройкой `SESSION_LIFETIME_SECONDS`, по умолчанию он составляет 28800 секунд. `GET /api/v1/auth/me` возвращает текущий аккаунт, а `POST /api/v1/auth/logout` отзывает текущую сессию.

Администратор и диспетчер могут читать и изменять расписание и справочники. Читатель может только читать их. Управление аккаунтами доступно администратору: `GET /api/v1/users` возвращает список, `POST /api/v1/users` создаёт аккаунт по полям `username`, `password`, `role`, а `PATCH /api/v1/users/{id}` меняет поля `role` и `is_active`. Роли: `admin`, `dispatcher`, `reader`. Пароль должен содержать от 8 до 128 символов. Блокировка через `is_active: false` отзывает все сессии аккаунта. При изменении роли новые права действуют сразу.

Запрос без действующей сессии получает 401, а запрос с недостаточными правами получает 403. Эндпоинты проверки состояния `/health`, `/health/live` и `/health/ready` остаются открытыми для инфраструктуры. OpenAPI-контракт доступен на `/docs`.
